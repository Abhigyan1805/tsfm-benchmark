# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

## Sharp edges

- `src/tsbench/base.py` is the frozen fleet-wide contract (`Forecaster`, `ModelInfo`, `RESULT_COLUMNS`). The data, model, and GPU slices import these names; never redefine or reorder them. `train_seconds` sits immediately after `peak_mem_mb`; it is the measured fit/train wall-clock for families that train or fit (classical, ML, deep) and empty only for the `baseline` and zero-shot `tsfm` families.
- `tsbench.evaluation.contract` is the single import site for the frozen `tsbench.base` contract: it uses `tsbench.base` when importable and otherwise falls back to a byte-identical schema, so the rest of the data/evaluation code and its tests never import `tsbench.base` directly. Keep the fallback in lockstep.
- `configs/models.yaml` keys and entrypoints are frozen fleet-wide. The registry refuses entries missing `license` or `revision` at load time, and refuses instantiation of non-permissive or unknown licenses unless `TSBENCH_ALLOW_NONCOMMERCIAL=1`. `ModelRegistry.instantiate` is the only public construction path (the resolver is private) so every registry construction passes the license gate. The runner routes a registry-known model through `instantiate` first and falls back to a config-declared `entrypoint` only when the registered module cannot be imported (the not-yet-landed-module stub fallback); a registry-unknown model may declare its own entrypoint only when the run opts in with `TSBENCH_ALLOW_UNREGISTERED=1` (parsed like `TSBENCH_ALLOW_NONCOMMERCIAL`) and the config declares a valid `family` and an allowlisted `license`, which are then recorded in `run.json`'s `unregistered_models`; the config key is stamped as the row's `model` and the declared family as its `family`, and `make report` surfaces the declared license in the summary's `unregistered`/`unregistered_license` columns. Run `make licenses` to print the manifest.
- Experiments run through `python -m tsbench run --config <experiment.yaml>`, which dispatches to `tsbench.evaluation.runner.run_experiment`. `src/tsbench/__main__.py` is the required shim for `python -m tsbench`. The CLI catches the runner's `RunnerError` and prints an `error: ...` line instead of a traceback; other exceptions propagate.
- The local-family backtest configs are `configs/experiments/backtest.yaml` (24h) plus `backtest_h{48,96,192}.yaml` (the primary 24/48/96/192 sweep; `make backtest` and `make horizons`). They are deliberately **bounded**: `stride: 240` samples 21-22 origins per series instead of the manifest's 24-step stride, and `track_memory: false` because `tracemalloc` makes statsforecast `auto_arima` ~3.5x slower (41s vs 12s for one 22-origin series). The bound is declared in each config's `subset:` block (stored verbatim in `run.json`) and in `REPORT.md`; `peak_mem_mb` is empty when tracking is off. `ExperimentConfig.track_memory` and `.warmup` thread through to `backtest_windows`.
- The GPU-tier configs `configs/experiments/gpu{,_h48,_h96,_h192}.yaml` run the deep and zero-shot TSFM families on the **same** frozen CPU windows (context 168, stride 240, same manifest/seed). They set `track_memory: true` (so `peak_mem_mb` is a GPU-host-only column: CUDA allocator peak on a GPU, host `tracemalloc` peak otherwise, empty for the CPU configs) and `warmup: true`, which primes the TSFM checkpoint load and TimesFM compile before the first scored window so it never skews that row's `latency_ms`. `configs/experiments/gpu_probe.yaml` (smoke fixture) and `gpu_pilot.yaml` (24 series x 1 origin, real data) validate a session before the full sweep; keep pilot output outside `results/` so `make report` never merges it.
- Slices own disjoint paths by design (data/evaluation, local models, GPU models). Check `PLAN.md` and the current task brief before editing outside your slice.
- GPU tier: `src/tsbench/models/deep/` (seeded LSTM/Transformer) and `src/tsbench/models/tsfm/` (zero-shot TimesFM 2.5 / Chronos-Bolt). Heavy deps import lazily and are not CI extras, so trained-path tests skip without torch; TSFM tests use fake backends and never touch the network. Weights require `TSBENCH_ALLOW_MODEL_DOWNLOAD=1`, and TimesFM 3.0 ids are refused. The TSFM wrappers cache the loaded backend and (TimesFM) the compiled horizon at process level, because the rolling-origin backtest builds a fresh model per window; `scripts/kaggle_run.py experiments` packs pending experiment configs into a GPU kernel that clones a pinned `--ref`, checksum-fetches the dataset, runs each config, and downloads a results tarball, resuming by `config_hash` (it refuses a ref lacking the backend cache). The GitHub repo is **private**, so the kernel cannot `git clone` it anonymously: the verified route bundles the pinned ref (`git bundle create`) into a private Kaggle dataset and passes `--repo /kaggle/input/<bundle> --dataset-source <owner>/<dataset>`. The generated kernel resolves both Kaggle mount layouts (`/kaggle/input/<slug>` and `/kaggle/input/datasets/<owner>/<slug>`), refreshes its results bundle after each config (run dirs live in `/tmp` until bundled into `/kaggle/working`, so a runtime limit would otherwise discard completed configs), and Kaggle requires the kernel title to slugify to the id slug (`default_title`). The job route is `scripts/serve_endpoint.py` + `scripts/colab_run.py`. All routes with exact commands live in `docs/colab-handoff.md`.
- `.gitignore`'s `/data/` pattern anchors to the repo root, so `src/tsbench/data/` is linted and tracked normally; the committed `data/manifests/` files were force-added and any regeneration still needs `git add -f`.
- Dataset downloads and run outputs live under the gitignored `data/` and `results/`. The frozen split manifest is the exception and is committed under `data/manifests/`; keep `data/manifests/checksums.sha256` in sync after regenerating. Each run's raw telemetry (`results.csv` + `run.json`) is committed under `docs/telemetry/{cpu,gpu}/<run_id>/`; `scripts/make_plots.py` (`make report`) merges that store with live `results/` by experiment-scoped root precedence: within a root it keeps the newest run per `config_hash`, but across roots each experiment is owned by the first root that provides it, so a stale committed-telemetry run is dropped even when it is the newest run for its own hash, and `summarise` fails loudly (naming the run ids, config hashes and roots) when genuinely different experiments collide on one summary row; it then writes `docs/results_summary.csv` + `docs/figures/`.
- Committed telemetry pins its experiment config by hash, so any cosmetic edit to a committed config (even note text in its `subset:` block) breaks `make reproduce` at `make report` until telemetry is regenerated or the text reverted; `tests/test_report.py::test_committed_telemetry_config_hashes_match_the_current_configs` pins every `docs/telemetry/{cpu,gpu}/*/run.json` to the current config's hash. Two related sharp edges: MASE's per-window denominator is the rolling `context_length` lookback, not the full train slice (`tsbench.evaluation.metrics.mase`), and `enumerate_windows` raises `SplitError` when no origin fits the geometry instead of returning `[]`.

## Commands

- Setup: `pip install -e ".[dev,models]"`; then `make test`, `make lint`, `make smoke`, `make licenses`. The `models` extra installs the local model tier's runtime deps (`xgboost`, `scikit-learn`, `statsforecast`, `statsmodels`); without it the tier's tests skip.
- Tests import `tsbench` without an install because pytest injects `src` via `pythonpath`; CI does a full editable install and runs ruff + pytest on 3.10 and 3.12. Local test/lint: `python -m pytest`, `python -m ruff check .`.
- Primary dataset: `python -m tsbench.data.build_catalog --materialize` (network, checksum-verified), then `make backtest`. Offline provenance: `python -m tsbench.data.build_catalog`.
